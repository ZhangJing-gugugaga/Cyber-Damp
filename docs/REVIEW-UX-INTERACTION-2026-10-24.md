# 交互体验审查报告（Goal v9 产品模式）

日期：2026-10-24。范围：`experience/visual-playground` 分支当前工作区（0.1.25 修复后、dist 与源码一致）。
方法：全量交互链路静态审查 + 隔离实测（真实 Explorer 桌面、隔离存档、探针目录限定、CDP 只读诊断 + 原生鼠标/截图）。测试实例已退出并恢复，探针对象已删除，未触碰用户存档与真实图标。

## 总体结论

核心闭环（选城 → 天气 → INIT 改图标 → 擦拭 → 采摘 → 购买 → 恢复/退出）在真机上端到端走通，视觉与文案完整度高于前几轮记录；但**"发现入口 → 获得反馈 → 保持状态同步"这条体验主线当前有 3 个断点**：胶囊完全不可交互（P0）、托盘暂停是死控件（P1）、护理台状态陈旧（P1）。三者都不是新架构问题，是接线遗漏，修复成本低。

## 逐旅程发现

### 1. 启动与找入口

- **P0 · 天气胶囊在产品模式完全不可交互（点击、拖动都失效）。** 证据链完整：
  - 原生模式装配时通用通道绑定空窗口：`src/main/index.ts:60` `registerHandlers(() => null, () => null)`；`window:setIgnoreMouseEvents` 处理器只作用于该空引用（`src/main/ipc/register-handlers.ts:84`），调用被静默丢弃。
  - 胶囊创建即整体穿透（`src/main/window/capsule-window.ts:100`），渲染层悬停时请求取消穿透（`src/renderer/capsule.ts:61`）永远无效。
  - 实测：窗口静止与真实悬停后 `WS_EX_TRANSPARENT` 均为 True；页面收到 12 次真实 mousemove（forward 生效）但 `__clicks=0`；`WindowFromPoint` 命中点返回桌面 SysListView32 —— 真实点击会落到桌面而非胶囊。
  - 连带后果：`capsule.ts:64` 点击开护理台失效；胶囊上的"点击选择城市"是反向引导；`-webkit-app-region: drag` 拖动同样失效，位置记忆功能（capsule-window.ts:124-131）无入口可用。**当前唯一入口是托盘。**
  - 与 0.1.25 修复的城市选择 bug 同类（通道注册了但绑在空窗口上），属回归高发区，建议补一条"原生渲染层发起的窗口级 IPC 必须落到真实窗口"的契约检查。
- P3 · 原生模式无启动反馈窗（`showStartupFeedback` 仅旧模式调用，index.ts:68）。实测启动本身很快（35 项桌面：布局 294ms、图标 759ms，胶囊秒级出现），可接受，如实记录。
- P3 · 胶囊自动隐藏/恢复未生效：启动日志 `SetWinEventHook FFI 不可用…Unknown or invalid type name 'WinEventProc'`（dist/main/native/win32-foreground.js:36）。GOAL 文档 A12 以探针记 PASS，生产路径实际未装上。胶囊本就不置顶、被应用遮挡属正常 z 序，用户感知有限，但属"探针通过≠生产生效"的又一例。

### 2. 首次引导（护理台）

- 布局与文案完整：欢迎页说明玩法来源、城市搜索、首批摘要、24 币奖励、可跳过，均有。
- **P2 · 不选城市也能一路完成引导并领奖**：`care.ts:521-532` 对城市无校验，step1"完成练习"即调用 `onboardingDone()` 发 24 币（实测：未选城 → 币 0→24）。之后游戏停在 wait-weather，新用户未必明白"为什么桌面没变化"。
- P2 · 城市搜索偶发失败且无自动重试：实测首次搜索返回"搜索失败，可重试"，数秒后同接口直调成功。首次体验有翻车概率，建议失败自动重试一次。
- P3 · "去挑一件工具吧（可选）"出现在引导浮层内，但浮层不提供去小铺的路径，文案与可操作项脱节。

### 3. 等待首批与状态反馈

- **P1 · 护理台状态不自动刷新，重开窗口也是旧数据。** 状态只在页面加载和本页动作后拉取（care.ts 各 reload 调用点），关闭=隐藏（management-window.ts:93）导致再打开是同一个陈旧 DOM。实测：INIT 已在主进程写入 stage3 霉变+成熟菇，护理台仍显示无徽章、无材质、无快速处理；`location.reload()` 后全部立即正确。**没有任何手动刷新入口**；"都收拾好了，桌面很干净"的空状态可能在桌面已发霉时出现。
- **P1 · 胶囊不随城市设置刷新**：仅加载时与 30 分钟定时刷新（capsule.ts:66-67）。实测选完杭州后胶囊仍显示"点击选择城市 / 待选择城市 / --°C"。天气接通是本产品最重要的首次反馈，却要等最多 30 分钟或重启。

### 4. 日常护理（工作台）

- 材质管线视觉达标：霉斑材质、蘑菇分层、霉变·重徽章、🍄可采标记、列表按污渍优先排序均正确渲染（刷新后）。
- **P1 · 护理进度条跨会话归零，松手也不刷新**：
  - `care.ts:178` 在恢复已保存擦除洞**之后**量取 dirtInitial，进度永远按"剩余污渍"重算——实测存档 careProgress=0.627，重开窗口进度条显示 0%。
  - `endWipe`（care.ts:255-261）不调用 `updateProgressUi`：实测松手时条上停在 43%，存档实际 62.7%，直到下次节流刷新才更新。用户感知是"进度不可信/像丢了"。
- P3 · 未选中对象时"海绵/快速处理"按钮仍可见可点，点击静默无操作（按钮显隐只在 selectObject 里管理，care.ts:301-302；finishCare 无 currentId 时早退无提示，care.ts:267）。
- P3 · 蘑菇层空 `src=''` 显示破图占位符（care.ts:155），无菇的受损对象左上角有破图小图标。
- P3 · 擦拭交互本身（按住、掩码、节流保存、≥90% 自动收尾）实测工作正常；擦到图标透明区会记掩码但无视觉/进度副作用，可接受。

### 5. 收获与养成

- 采摘 +4 币、收藏入册（ species 回退逻辑核实无 bug：'oyster' 仅为无品种时的回退，native-care.ts:72）。
- 小铺：购买有确认对话、余额扣减、"已拥有"状态正确；商品描述清楚。P3：价格在行尾与按钮上重复展示（"12 币"+"12 币购买"）。

### 6. 暂停、恢复与退出

- **P1 · 托盘"暂停/继续"是死控件**：`management-window.ts:53` 只翻转内存 `status.paused` 并广播；原生模式下没有任何消费者（游戏暂停状态在 `save.native.paused`，只能经护理台设置页 `native:setPaused`，care.ts:421-425；care.ts 未注册 management:onStatus）。实测推理成立：托盘暂停后游戏照常，护理台的暂停勾选也不会同步。
- 恢复并暂停 / 继续游戏 / 完全退出全链路实测通过：确认对话文案清楚；恢复后探针 desktop.ini 逐字节还原（md5 与创建时一致）、退出日志 `[icon-restore] 退出恢复` 逐项 restored、进程 exit 0 无残留。
- P3 · 关闭护理窗=隐藏到托盘的语义，只在退出确认文案与使用说明中解释，窗口本体无提示。

### 7. 可及性与细节

- P3 · 对象列表/收藏/小铺均为 div 结构，无 tabindex/role/键盘激活；按钮可 Tab 但整个工作台键盘不可达。悬停/按下/禁用态基本齐备，但列表项 hover 反馈弱。
- P3 · care.ts `refreshStatusOnly` 与 `reload` 完全重复（care.ts:551-559），代码卫生。

## 实测通过项（有证据）

- 0.1.25 城市选择修复有效：searchCity 从护理台与胶囊双端调用均成功。
- 天气实数接入（杭州 18.7°C）、INIT 真实写入探针图标、回显/恢复/暂停门禁（restored=true 时事件不回写桌面）。
- 擦拭掩码持久化与重开还原同一批擦除洞；≥90% 自动收尾逻辑在位。
- 采购/采摘/收藏的金额与状态一致（24→28→16 币链路核对）。
- 单实例锁、退出恢复、还原逐字节核对、无桌面残留。
- 设置页文案诚实（自启行为、恢复暂停后果、Open-Meteo 署名可见）。

## 修复优先级建议

1. **胶囊交互接线**（P0）：为原生渲染层建立按 sender 的窗口注册表，`window:setIgnoreMouseEvents` 等窗口级通道落到真实窗口；补"原生点击胶囊打开护理台"的原生回归项。
2. **托盘暂停接通**（P1）：click 里调用 `setNativePaused` 并回读状态刷新托盘文案与护理台勾选。
3. **护理台状态同步**（P1）：窗口 show/focus 时或定时（30-60s）重拉 native:status；或主进程在 INIT/DAILY/回显后主动推送。
4. **进度条语义**（P1）：持久化初始污渍量（或直接展示 careProgress），endWipe 后立即 updateProgressUi。
5. **胶囊刷新**（P2）：setLocation / 事件循环成功后主进程通知胶囊立即 refresh。
6. 其余 P2/P3 按上表逐项处理。
