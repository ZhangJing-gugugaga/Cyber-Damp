# 回南天当前功能、交互与留存评估

日期：2026-10-25。对象：本地 `experience/visual-playground` 工作区，package 版本 0.1.25，HEAD `3557d92`，包含评估开始时已有的未提交修改。

**结论：有吸引人安装试玩的题材，也有成为长期桌面陪伴物的潜力；当前版本尚不足以支撑稳定留存。** 主要损失发生在首次可玩性、状态可信度、可感知变化和重复互动的乐趣。仅修复错误能恢复可用，但不能自动补齐持续回来的理由。

这是工程与产品判断，不是真实玩家留存统计。本次未启动生产实例改写真实图标，未重新安装或完整执行原生 UAT。未把历史截图、规则测试或隔离模拟称为当前包的实际手感通过。用户既有源码、存档和真实桌面未修改；本次仅新增本报告。

## 2. 玩家现在实际上能玩到什么

[management-window.ts](../src/main/window/management-window.ts) 的 `NATIVE_MODE` 和 [main/index.ts](../src/main/index.ts) 确认：正常启动走原生模式，旧覆盖层仅在特定环境分支运行。

| 能力 | 当前生产路径 | 对体验的意义 |
|---|---|---|
| 原生桌面 | 文件夹/普通快捷方式图标引用变化，保留 Explorer 原生输入 | 避免替身对单击、双击、框选、拖放的竞争，是正确的可靠性取舍 |
| 天气胶囊 | 地点、天气、温湿度、时间；普通非置顶窗口、托盘入口 | 有实用性，但 Win+D 后允许隐藏，不能把不可见误报为新缺陷 |
| 自然变化 | 首批 5–10 个，候选不足按实数；日常全局每天至多一个对象推进一级 | 安静，但变化量很低，需要明确而克制的可发现反馈 |
| 护理 | 普通窗口里的海绵擦拭、免费快速处理、部分进度保存设计 | 已有可操作核心，但持久化和反馈仍有缺陷 |
| 采摘、收藏、小铺 | 5 个品种标识，3 类主要菇形；每朵 4 币；两件商品 | 有闭环骨架，内容与表达仍薄 |
| 退出与控制 | 暂停、恢复桌面并暂停、继续、退出恢复、自启设置 | 关系到敢不敢常驻，比商城规模更基础 |
| 绳索、风扇、吹气、旧动态蘑菇等 | 大量代码和资产保留，但不在默认新版玩法入口 | 不计入当前功能丰富度，也不建议为恢复它们重新引入覆盖层 |

新版从“动态桌面场景”收敛成了“会变化的原生图标与窗口护理”。这符合新约束，但也减少了玩家随手拨弄、得到即时回应的机会。必须用当前允许的窗口内反馈和桌面结果表达补回吸引力。

## 3. 可玩性与状态可信度：优先处理的具体发现

### 3.1 当前护理台初始化会中断（阻断级，隔离复现）

位置：[care.ts:620](../src/renderer/care.ts#L620)、[care.html:68](../src/renderer/care.html#L68)。

页面城市容器只有 `class="row city-picker"`，没有 `id="city-picker"`。装配阶段按 ID 取节点，再调用 `mountCityPicker` 的 `root.append(...)`。类型断言不能让空节点变成真实节点。

复现：从真实 care.html 提取全部 ID；把当前 care.ts 经已安装 TypeScript 转译，在隔离 DOM 接口中执行，保留按真实 ID 返回 null 的行为。结果：`Cannot read properties of null (reading 'append')`；`native.status` 调用次数 0；启动遮罩未移除。异常发生在末尾正常 `reload().finally(...)` 之前。

影响：当前源码一旦按此打包，护理台可能持续显示加载中，玩家到不了核心互动。该检查是隔离装配复现，尚未在安装包中重新走查。最小修复应统一现有容器与挂载方式，同时避免把已有静态选择器和新增选择器重复挂上。

### 3.2 擦拭掩码只保存了前八行（高优先级，函数往返复现）

位置：[care.ts:122](../src/renderer/care.ts#L122)。

工作掩码是 64×64=4096 个二值格，需要 512 字节。编码循环只输出 64 字节，解码也只读取 64 字节，恢复的只是前 512 个格，即顶部八行。

复现：直接提取当前编码、解码函数，把第 2000 和 4095 格置为 1，编码再解码。输入 2 个已擦格，输出 0 个；实际保存 64 字节，完整应为 512 字节。

影响：中下部擦过的位置在重新选择、刷新或重开后消失。进度值可能保存了，但显示按重建后的画布重新计算，玩家会认为刚才白擦了。此前修改进度基准和采样方式没有解决这个独立根因。

### 3.3 每日规则缺少常驻运行的触发接线（高置信静态发现）

位置：[native-handlers.ts](../src/main/ipc/native-handlers.ts)、[management-window.ts:182](../src/main/window/management-window.ts#L182)、[register-handlers.ts](../src/main/ipc/register-handlers.ts)。

全源码搜索 `runNativeEventCycle`，生产调用在启动、设置城市和显式继续游戏。胶囊的 30 秒刷新只取状态和天气；`weather:current` 仅调用 `getWeather`。没有找到跨日天气检查触发日事件的接线；原生模式唤醒回调也只发布管理状态。

影响：规则测试可以证明“调用时正确地最多推进一次”，却不能证明程序常驻一整天会自己变化。玩家可能挂着不变，重启后才有变化。这直接损伤天气驱动桌面微生态的核心承诺。应复用天气缓存检查与电源唤醒入口触发已有协调器，不增加高频轮询，也不改变每天至多一次的硬规则。跨日、睡眠唤醒仍须隔离真机验证。

### 3.4 胶囊点击与拖动仍有职责冲突（官方规则支持的高风险，未做新原生复测）

位置：[capsule.html:17](../src/renderer/capsule.html#L17)、[capsule.ts:66](../src/renderer/capsule.ts#L66)。

穿透 IPC 的空窗口问题已在工作区修补，但整个胶囊仍设置 `-webkit-app-region: drag`，同一元素又监听 DOM click 打开护理台。Electron 官方说明可拖动区域忽略指针事件，互动区域需明确 `no-drag`。

因此“取消永久穿透”不能视为“点击胶囊已修好”。应明确可点击区域与拖动区域，按当前规格验证拖后不误打开；本次不把此风险写成新原生实测失败。[官方说明](https://github.com/electron/electron/blob/main/docs/tutorial/custom-window-interactions.md)

### 3.5 完整护理后的对象仍被旧损伤族锁定（纯领域复现）

位置：[native-care.ts:38](../src/world/native-care.ts#L38)、[native-events.ts:161](../src/world/native-events.ts#L161)。

护理清零 stage，但保留原 family；日常候选过滤将任何非 null damage 都按原 family 判断。复现：焦化对象完整清理，推进时钟到 11 天后，给定多云/80% 湿度（damp40/mold60/char0），该对象仍不可入选，因为其 family 仍是 char。

影响：干净对象没有真正回到“按当前天气引入效果”的状态，季节变化的多样性会进一步下降。应先明确干净与保留幼菇的状态语义，再最小修复过滤/推进逻辑，不能直接丢弃菇或更改免疫约定。

## 4. 视觉：有统一语言，生命感和结果表达仍不足

值得保留的是：深雨青、苔绿和琥珀的统一色板；真实图标作为主体；桌面和护理台使用同一个材质模块与稳定款式；清理与蘑菇分层。这比桌面一个效果、护理台另一种效果更容易建立一致认识。

主要问题是视觉层级服务于“管理对象”，对“接触物件”的表达不足。列表、徽章、卡片、按钮已齐，但工作台仍以静态图标加一层可擦图为主。工具图片留在按钮里，没有跟手的接触姿态；未见护理页接入旧 Sfx、泡沫/碎屑、完成与首次发现的反馈。小铺两条商品行更接近功能设置，物件陈列与收藏展示的吸引力有限。

当前原生 ICO 是离散状态图片，不具备旧 Pixi 场景的连续伸展、呼吸、根部摇摆。不能要求在桌面持续写图标来补动画；更合理的是在护理窗口复用已有分层资产、效果预览和音效控制器，桌面保持稳定，结果发生时同步一次。

32/48px 真实可读性仍未完成当前版用户视觉验收。256px 下材质漂亮，不足以证明日常桌面上既能看出变化又能认出原图。优先补浅/深/复杂壁纸下的原尺寸对照，而非继续增加同类大图。

## 5. 丝滑体验：需要分别看系统、响应与反馈

**系统层面**：保留 Explorer 输入、取消全屏覆盖层，是有利于桌面可靠性的改变。后台提取图标、异步网络和有界小窗也有可复用基础。但本次没有当前包的 CPU、GPU、内存、输入延迟或帧时间采样，不能写“已流畅”。A24 的固定场景性能采样仍缺。

**操作层面**：护理页在 pointermove 立即擦除，这是正确方向；进度条却和每 1200ms 的保存节流绑在一起。画面在擦、进度隔一段才跳，影响反馈的一致性。松手补刷已写，但不等于过程中跟手。`wipeAt` 只擦采样点，没有相邻点连线，快速横扫可能留下断续圆洞；这是静态风险，需真实鼠标检验。失焦结束手势也需独立检查，当前页未见 blur 监听。

**结果层面**：清理与采摘先返回成功，图标合成/引用更新异步执行且失败主要写日志。需要区分“护理进度已保存”和“桌面外观已同步”，并给失败恢复入口；不能让玩家靠猜测判断操作是否成功。

Electron 官方要求避免阻塞主进程。当前状态轮询会读存档、序列化图标，护理页还会整页重建；这些是应测热点，不是已经证明的卡顿根因。优先量取打开、擦拭、松手、完成同步和隐藏后的占用，不凭函数数量推断性能。[官方性能指南](https://github.com/electron/electron/blob/main/docs/tutorial/performance.md)

Context7 另核对了 Pixi 8.21.0 的 ticker 停启与限帧能力。但新版默认护理页不是 Pixi 主循环，不能拿优化旧 ticker 来冒充修复当前体验。[版本文档](https://github.com/pixijs/pixijs/blob/v8.21.0/src/__docs__/concepts/render-loop.md)

## 6. 留存：首局收获不稳定，持续动机尚未建立

**首次成功没有被组织出来。** 引导的“完成练习”实际是文本页上的按钮，未让玩家完成一次真实或隔离练习的擦拭。奖励到账可以很快，但玩家可能还没有体验到清理和收获的乐趣。首次打开列表也不自动选定可操作对象。

**首局不保证看到蘑菇。** 直接调用当前 `planInit`，固定 10 个候选、多云/80% 湿度、22°C，对 1–10000 共一万种种子模拟：平均首批 7.4972 个；1395 局至少一枚成熟菇（13.95%）；7237 局连幼菇也没有（72.37%）。这是指定条件下的规则模拟，不是用户数据，也不是所有城市的普遍概率。

当前内置离线快照为晴/67% 湿度，权重 damp30/mold0/char70；一直走该默认快照的新存档不会凭该天气生成霉变与蘑菇。这不是反对默认天气，而是提醒：开箱可运行与开箱能体验核心乐趣不是同一件事。可以使用明确标识的窗口练习对象保证一次清理/采摘演示，不改真实天气、不额外推进真实桌面额度。

**日常可见变化太容易被错过。** 一个对象一级的变化发生在几十个原生小图标中，玩家未必知道“今天哪里不同”。保持每日上限，同时提供一次轻量变化摘要、胶囊上的克制状态提示或打开护理台时的前后对照，比增加自动弹窗更符合桌面用途。

**清理与养菇的动机存在拉扯。** 清理获得 240h 防霉，能保护用户桌面，却减少同一对象的蘑菇来源；多数首局又没有可采菇。观察玩家可能觉得清理会把有趣变化收走，收集玩家可能不愿清理。应在界面解释“清理保留已有蘑菇”，并把少量可自由体验的窗口交互和真实桌面保护分开设计，不增加强制护理。

**经济很快失去用途。** 新手 24 币，两件商品 12+8=20 币，买完还剩 4 币。因此采菇收入不是当前有力的持续动机。免费快速处理与手擦结果相同，若手擦没有额外感官乐趣，玩家自然会直接点掉。

这不意味着应该扣掉奖励、削弱快捷处理或堆更多昂贵道具。项目定位是轻量桌面玩具：更适合少量有辨识度的装饰、可陈列收藏和变化记忆，让币成为附带收获。收藏已有来源对象和首次日期，但五种名称只复用三类主要造型，也缺少有吸引力的陈列与新发现表达，尚不足以形成鲜明的拥有感。

## 8. 建议执行顺序与验收方式

| 顺序 | 做什么 | 如何判断有改善 |
|---|---|---|
| 先恢复可玩 | 统一城市节点/挂载；完整保存掩码；明确胶囊点击拖动；补跨日/唤醒调度；修干净对象族过滤 | 正式窗口能打开；擦中下部重开保留；胶囊点开/拖动可靠；连续常驻跨日发生且至多一次 |
| 再做一个完整体验 | 从发现变化、选中对象、擦拭、松手保存到桌面同步，打磨一条完整链路；复用已有工具/音效/反馈资产 | 新用户不靠讲解完成一次操作，能说出改了什么；快速处理仍保留 |
| 再加强回来理由 | 克制的变化摘要、前后对照、收藏陈列与首次发现；少量可选装饰 | 第二天能发现变化，并愿意主动打开或互动；没有增加工作干扰 |
| 再判断扩充 | 根据真实试玩决定是否扩品种/道具 | 先看到重复自愿使用，再增加内容，避免只增加按钮 |

建议下一轮找 5–8 位不了解项目的用户做首次使用走查，再观察约一周。该人数是发现问题的建议，不是统计显著性样本。每人记录：能否找到入口、能否完成首次护理、是否注意到次日变化、为何再次打开、何时隐藏/暂停/退出，以及这些行为的原因。

区分三种结果：愿不愿保留安装；愿不愿让它常驻；会不会主动再次互动。进程长期开着不能等同主动留存，更不能把本地 session_start 计数当作有效体验次数。当前原生护理页未见对发现、护理完成、首次采摘等关键节点的完整记录；若补测量，先用自愿、最小化、无路径/文件名的本地计数，不能悄悄增加外部上报。

性能应覆盖正式安装产物的冷/热启动、护理窗打开、连续擦拭、快速拖动、松手重开、后台隐藏、断网和休眠唤醒；标注机器、分辨率与 DPI。当前既有 ≤2 秒胶囊、≤1 秒主窗反馈等预算可作工程门槛，最终“丝滑”仍需要真实鼠标和用户感官确认。
