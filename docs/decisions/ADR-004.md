# ADR-004: 虚拟文件树为 MVP 唯一数据源（接口先行，真实桌面扫描后置）

## Status: Accepted (2026-10-16)

## Background

PRD 2.1 的"替身托管"机制要求扫描真实桌面、隐藏原生图标图层（Windows SysListView32 句柄操作）、双击替身打开原文件。该机制安全性要求极高（绝对安全红线：绝不修改用户真实文件），且句柄级操作在崩溃恢复上需要守护钩子等重机制。项目总监派发口径明确：MVP 数据源为虚拟文件树模拟。

## Decision

MVP 唯一数据源 = 确定性虚拟文件树生成器（world/virtual-desktop.ts，mulberry32 种子，同一天同一桌面）。物理替身与交互全部作用于虚拟节点。

架构上以接口先行保留演进路径：

```ts
// shared/types/file-source.ts（概念形态）
export interface FileSource {
  list(): Promise<FileNode[]>;
}
// MVP: SeededVirtualFileSource；后置: RealDesktopFileSource（fs.stat + mtime 读取）
```

真实桌面扫描（只读元数据 + 原生图标图层隐藏 + 崩溃恢复守护）列入 P2，且届时必须单独过安全评审：只读 stat、不碰文件内容、句柄操作带守护钩子与秒级恢复。

## Consequences

正面：绝对安全红线从"小心操作真实文件"变为"根本不碰真实文件"，风险归零；确定性种子使演出、调试、回归可复现；无权限/无杀软误报问题。
负面：MVP 体验与用户真实桌面无绑定（老文件的 mtime 是模拟的）；切换到真实源需要实现 FileSource 并重新设计"打开原文件清零冷落"的链路。该代价被判定为可接受。
