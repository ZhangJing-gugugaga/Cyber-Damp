# 回南天：体验方向修订与后续开发计划

日期：2026-10-21。状态：用户已批准并建立活动Goal，开发进行中；源码、独立预览、打包和原生验收分别记录。

## 2026-10-22 最新用户修订：先收口功能与性能

用户重新反馈运行卡顿、动画前额外等待、工具与图标操作冲突。历史性能认可不作为当前达标结论，先解决这些可复现问题，再扩充内容。已采纳：默认浏览；显式选工具后只执行工具动作，Esc退出工具并取消手势；不能拿剪刀双击打开文件，悬停蘑菇不能自动变成剪刀。切换应用/暂停取消旧手势。

本轮追加：材质不污染图标下方白色文件名；移除“开始四秒播放”按钮，双击启动程序后，在资源和安全接管完成时自动播放，原回放3–5秒要求保留。计时分别记录启动准备、接管和回放，不能把回放四秒当成总启动四秒。

继续遵守GitHub优先与最小适配：复用Electron窗口/快捷键、现有工具箱/命中/动作/恢复监护、既有材质和图集。动态效果包可替换作为后续方向，当前不宣称已热插拔，也不在本轮输入/性能修复时建立大型插件框架。

## 当前 Goal 与决策优先级

在已认可的原生布局、连续霉变和良好性能基础上，复用旧版资产与成熟实现，恢复桌面图标的原生交互感，重构统一的游戏式商城与桌面控件，扩充多种可辨识、连续变化的动态样片，再集成、打包并进行真实桌面与用户观察验收。

本文件合并原始 [2026-10-20 Goal](2026-10-20-desktop-mildew-goal-prompt.md) 与用户最新体验反馈，优先于旧文档中的冲突要求。原始附件、冻结样片、旧 UAT 和采样数据保持原貌。原 Goal 未被整体验收，本次也不将它标记完成。

用户当前反馈作为本轮基线：发霉正常、排版已认可、性能优良且其他工作几乎不受影响；不足在动态样片种类少，桌面按钮分散且与商城不统一，单击选中反馈缺失。双击打开正常，仍须在改动后回归。

## 本轮方向变化

1. **旧版优先复用。** 按素材/代码/行为逐项评估，不把旧版整体作废。能复用的代码绝不重新写，Codex 只补缺少的功能；每项编码前先查 GitHub 的现成项目、官方示例和本项目已有实现。
2. **性能收口。** 用户已认可当前使用表现。只做相关回归，不再为追逐旧预算反复优化，也不把新增 30 分钟专项采样作为当前体验迭代的门槛。明显卡顿、内存持续异常增长或操作受阻出现时再定位；历史数据不改写为技术通过。
3. **UI 重新定位。** 商城与设置是游戏交互后台，桌面是游玩场景。采用紧凑操作层级、物品展示、明确状态与一致反馈，替代宣传式大标题/口号布局。统一并收拢桌面入口。
4. **交互补回。** 恢复原生观感的悬停、单击选中、空白清选、焦点反馈，保留正常双击打开和拖动；支持 Ctrl 多选等必要修饰键语义。需要模拟的视觉与真正 Explorer 状态明确区分，不把“画了高亮”宣称为完整 Shell 行为。
5. **样片提升为主线。** 新增多效果连续样片，至少覆盖发霉、萎缩/缩水、焦化卷边、皱褶。允许实验吸湿鼓胀、软塌及护理恢复，后续可按用户观感替换。
6. **遮挡放宽至 90%。** 旧 55% 上限撤销。最高状态可遮挡到原图有效可见区域的 90%，不是每个图标必须达到 90%；正常桌面比例下仍应认出对象，文件名和邻近图标可读。变形不改变真实图标位置/显示布局，也不改写真实文件。
7. **彩蛋使用原图。** 优先已有资产和网上原始图片，不要求重新生图；保留来源和许可记录，区分研究预览与随包使用。

## 继续保留的原 Goal 要求

真实 Shell 数量、位置、大小、DPI/多屏处理及读取失败保留可用桌面；连续局部演变、稳定菌落、根部附着与轻微摆动；3–5 秒且默认 4 秒的启动回放；慢速错峰日常演进；护理/存档合并、改名修改换新、无离线惩罚；干燥留斑、清洗显式触发；普通菇品相差仍可采、特殊菇遵守 PVZ 铲子要求、火山菇无爆炸、蜗牛纯装饰；单一普通管理窗、快捷键冲突与托盘备用入口、关闭/暂停/隐藏/退出区分；普通应用遮挡和焦点不受侵扰；退出恢复、重复启动、异常恢复、文件变化与休眠唤醒验收。

这些要求按改动与里程碑补齐，不因本次视觉扩展被删除。完整批量设备/经济结算仍保留在后续需求中，不用复杂经营系统支撑本轮 UI。

## 调研结论与复用入口

详细来源、许可证和项目现成能力见 [游戏 UI 与复用调研](../../research/2026-10-21-game-ui-and-reuse.md)。主要参考 VPet 的桌面工具与购买窗口分工、Rusty's Retirement 的低干扰定位、本地游戏技能的 HUD 可见性预算；现有 Pixi Filters6 与项目材质能力优先于新写滤镜。商业游戏只作产品参考，其他引擎的 UI 不直接搬入当前技术栈。

每项实施记录“检索来源 → 已有能力 → 复用位置 → 缺口 → 最小适配 → 验证”。源码、依赖和资产分别检查兼容性与来源；不为增加复用数量更换引擎或重写业务。

| P4：便携包与原生回归 | 类型/相关状态边界检查、构建、打包。按实际改动跑原生鼠标/键盘/截图；继续补原 Goal 中缺少的必要适配、状态和恢复证据 | 明确版本/哈希便携包、短对比录像、矩阵与剩余事项 | 不以源码截图代表包内资源，不以领域测试代表实际交互；正常/异常退出恢复，原布局不变。条件不足标记未测，核心缺陷修复后重测 |
| P5：用户观察收口 | 完成可独立开展工作后集中提供最小观察清单 | 用户评价“像游戏、交互回来了、变化丰富且可辨认、工作不受影响” | 生产效果须获用户认可才完成原 Goal。未满足项继续处理，不宣称全部完成 |

P2 的 UI 与样片可独立交替制作，但本轮不默认增加多代理团队或大型流程。每轮聚焦少量可见结果；代码检查完成后尽快形成演示与可运行增量，而不是连续多轮只新增诊断脚本。

## UI 的具体设计边界

- 桌面工具入口默认收起为一个小控件，展开呈现常用工具；天气、余额等可按需展示，不再散落多个常驻深色方块。选中后出现针对对象的上下文动作。
- 商城以“分类/物品展示/详情/购买与装备状态”为核心。道具和角色美术占主体；标题与文字服务操作，复用旧版图标和道具资源。采用有层级的少量面板，不禁止必要的物品格。
- 设置与商城在同一普通独立窗口，关闭管理窗不等于退出；隐藏默认暂停，暂停冻结演进；有托盘和可编辑快捷键。
- 悬停、按下、选中、已拥有、装备中、余额不足、操作成功/失败均有明确状态；不依赖颜色单独表达含义。键盘焦点可见。

## 样片与识别性

以文件夹、彩色应用图标、浅色文档三类真实比例对象查看。效果可以叠加，但不能把整个图标放大或重排来增强存在感；萎缩/卷边/皱褶只影响画面几何，选中与命中保持可用，名称不随材质缩没。根部/霉点位置与随机种子稳定，演变曲线和最终强度错开。

遮挡测量沿用独立 mask 并集与原图 alpha 可见区域口径，阈值改为 0.90；变形额外记录显示比例/轮廓变化。测量是辅助证据，不能单独证明“仍能认出是什么”。正常尺寸原图切换、邻近图标/名称观察及用户判断才覆盖感官要求。不得用 RGB 差异或一张放大成熟帧代替全过程。

首轮样片采用可组合参数，避免每种效果都创建全新系统。旧样片及来源文件冻结，实验另存；本轮计划不宣称 12 条样片已绘制。

## 最小用户观察清单

1. 单击选中与双击打开是否像桌面，严重变化后能否认出并点中对象。
2. 桌面按钮是否收拢，商城/设置是否像同一款游戏且操作清楚。
3. 发霉、缩水、焦化卷边、皱褶是否有区别且过程连续；更强遮挡是否仍可辨认。
4. 继续做其他工作是否仍几乎无影响，隐藏/暂停/退出是否符合预期。
