## 4. 规则域（每条规则只在此定义一次，其他章节引用编号）

### R1 原生图标替换与恢复

**支持范围**：仅文件夹与普通 `.lnk`。快捷方式仅 update 图标引用，目标、参数、工作目录、原生箭头等行为保持不变；文件夹仅修改必要图标配置，保留 `desktop.ini` 其他内容、原图标及必要原属性。原生文件夹属性在 Explorer 其他位置也会反映，不伪称"仅桌面变化"。

**禁止项**：改系统 DLL、全局文件类型关联、对象位置/名称/内容；新建快捷方式代替原对象；杀 Explorer、重建全局图标缓存、要求用户重启才能显示效果。

**写前落盘**：原始引用与恢复信息在修改前可靠落盘；原生刷新只针对必要对象。

**失败处理**：按R4执行有限重试或明确跳过，单个失败不阻塞其余可处理对象，在护理窗口给出简短原因；必交类型整体不通则报告阻塞，不得用替身绕过验收。

**恢复语义**：恢复的是用户原值，不是系统默认。恢复前核对当前引用归属；若已被用户自行更改，保留用户值并报告。删除/移动对象后不复活、不覆盖新同名对象；可可靠识别同一对象的改名则保留游戏状态，否则停止修改并说明。链接损坏、公用桌面无写权限等跳过而不阻塞其他对象，不要求全局管理员运行。

### R2 天气胶囊窗口

有界小窗口，绝非全屏幕布。可拖动并记住位置；重置布局回顶部中央；显示器拔插/DPI 变化后夹回可见工作区；不强移桌面图标，不建立覆盖全屏的透明宿主。

可见胶囊区域外不截获桌面点击，包括窗口透明留白；点击与拖动沿用系统拖动阈值区分，拖动结束不误打开护理窗口。

默认不压住普通应用、不抢焦点；全屏应用期间隐藏；不持续呼吸、闪烁或展开。点击胶囊打开护理台；右键提供隐藏、设置、退出。隐藏只隐藏胶囊，不暂停日推进，托盘始终是备用入口。

全屏检测先复用src/main/native/win32-desktop.ts已有GetForegroundWindow、GetWindowRect和koffi绑定；结合Electron screen的显示器信息，统一DPI坐标后判断前台非Shell窗口是否覆盖其显示器。用Windows官方SetWinEventHook的前台/位置变化通知触发检查，不截获或转发输入；这是对现有绑定的最小补充。阶段1必须验证同窗切入/退出全屏、切换前台、混合DPI多屏，以及恢复时不抢焦点。官方依据：https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook 。如该方案不适用，按R0查证成熟替代并记录适配证据；手动隐藏仅是临时入口，不能代替全屏自动隐藏验收。

玻璃优先调用 Electron / Windows 现有材质。Windows 11 22H2+ 的 Acrylic 需原生实测；低版本半透明降级；不得用 CSS 模糊胶囊自身文字冒充背景玻璃。

**技术冲突优先级**：不拦桌面点击、不压普通应用、不抢焦点 > 桌面及 Win+D 可见/可重新唤回 > 原生 Acrylic。**本稿写作时该组合尚未实测**，必须在阶段 1 做专项原型并记录实测结果；在此之前，任何验收项、进度报告或最终报告不得将其写成"已实现"。系统不支持材质只允许降级为半透明；若 Win+D 可见与其他硬约束无法兼得，先给出原型证据与恢复入口，继续开发独立功能，标为**待用户确认降级**，不得自行记 PASS，也不得把"可记录的半透明降级"扩展成强置顶或全屏透明覆盖层。不能把不可点击的 `electron-wallpaper` 直接当作"交互胶囊已实现"。

### R3 天气数据、城市与离线

**语义**：今日天气 = 所选城市最新 `current` 时刻气象条件，显示更新时间；不是当日最高/最低温或全天预报；来源可能是气象模型当前估计值，不冒称本地室内传感器或逐站实测。界面显示所在地室外天气参考。

**字段与格式**：至少 `temperature_2m`、`relative_humidity_2m`、`weather_code`，按官方编码解析；摄氏温度、百分比湿度、中文地点/天气名称，保留数据来源署名。

**地点**：首次设置由用户选择城市，不用时区推断或随机城市冒充定位；城市搜索用成熟地理编码接口。搜索失败或无结果时保留输入并可重试，不自动选随机地点。已有城市时采用待切换状态：新城市及其有效天气一起成功后再保存为当前城市；失败保留旧城市和对应缓存，说明仍显示旧城市并提供重试/取消。首次没有旧城市时可保存已选地点为待取数，显示待联网，不阻断护理、收藏、小铺与练习。缓存按城市坐标分开，绝不把旧城市的天气配上新城市名称。

**取数**：启动、唤醒、改城按缓存策略取数（参数见第 2 节）；不频繁刷新、不每帧请求。改变城市、手动刷新天气不能额外获得日事件或重新抽奖。

**离线**：有缓存而断网 → 显示最近值 + 更新时间 + 离线标记；无缓存 → 显示待联网，不显示假实况，护理/收藏/商城/演示仍可用。断网或无有效天气的日期不记已推进、不形成逐日积欠；恢复联网后只处理恢复当天允许的一次（见 R4）。

**缓存老化**：缓存年龄按该天气快照的current时间计算。30分钟内可直接使用；超过30分钟先尝试刷新，失败时可使用年龄不超过24小时的旧快照并明确标示更新时间/离线；超过24小时只可展示，不能作为新自然事件依据。温度必须为有限摄氏数值、湿度在0–100%、天气码属于R5集合；缺失或无效字段不能驱动自然事件。

**首次安装例外**：尚未初始化的首次安装是唯一例外——界面立即可用，但首批真实变化等待首次有效天气；无论等待几天，随后只完成原先那一批并占用完成当日额度，不发回归事件。已有进度的用户恢复联网只适用普通单次事件。

首轮天气请求按参数表总计最多3次，网络等待上限28秒（3×8秒＋1秒＋3秒）；到限结束本轮加载，显示“天气暂不可用，联网后开始首批变化”，保留重试与跳过引导入口。等待数据的状态可以持续存在，但界面不能持续转圈或阻止其他功能；后台仅按30分钟缓存刷新节奏、唤醒或用户重试再尝试。首次在线成功的验收与首次断网降级验收分开记录，后者不能代替前者。

**快照不可回写**：每次自然事件记录所用天气快照；天气刷新不改写已落地状态。

**许可与用途**：Open-Meteo Free API 只限非商业，不能因无需 Key 宣称免费商用；SDK 许可、数据署名与托管条款分别处理。本轮用途已由用户确认为本机及私下非商业体验，采用该接口并提供署名；安装包只私下交付。未来用途变更须另选有授权的接口/配置，不得沿用本轮结论。若服务对既定用途另有限制，或接口被阻断且无已授权替代，按真实阻塞报告，不把离线模拟当实况完成。

### R4 自然事件模型（权威定义）

自然事件只有两种，**同一时刻互斥**：`INIT`（一次性首局事务）与 `DAILY`（日常推进）。此外一切（外观回显、手动护理、退出恢复原图、首批摘要展示）都**不是**自然事件，不计额度、不消耗当日额度、不参与互斥判断。

所有原生写入仍由同一协调器串行管理：写前保存事件/对象/目标状态版本和恢复信息；同一对象的自然变化、护理、回显和恢复不能互相覆盖，过期合成结果不得落地。启动先核对未结算写入再调度新事件；已写成功而回执未存时，只补结算，不再推进。若跨午夜时无法确定成功日期，保守占用写入意图日及核对日的额度并报告，不在核对日再发第二个自然事件。INIT待处理对象暂不进入可护理列表；已成功项可正常护理，续作不覆盖它们。

#### R4.1 INIT（首局事务）

- **生成条件**：首次安装、城市已确认、取得首次有效天气。界面与原生桌面不等天气请求即可用。
- **目标集合**：一次抽取 K（第 2 节）；从真实 Shell 可见且支持、可写、可恢复的对象中，按原始 mtime 从旧到新取前 N=min(K, 可写且可恢复候选数)，mtime 相同按稳定对象 ID 排序。用 mtime 近似"最久未动"，不声称可靠得知"最久未打开"，不扫描文档内容、不递归计算目录体积。
- **固定性**：N 个目标、天气快照、随机状态与随机布局在事务建立时固定并持久化；**全生命周期不变**，每个对象至多成功一次。
- **执行跨度**：允许首个有效自然日批量完成；也允许崩溃重试或跨日续作日完成剩余**全部**对象，总数仍为 N。不得把 INIT 改成"每天只处理一个"，不得另抽一批，不得重抽天气/状态，不得扩大目标集合。
- **占用额度**：每个实际写入日与最终完成日各占用该自然日的唯一普通日额度；这些日子不再发 DAILY。INIT 未结束前不并行发 DAILY。
- **候选不足**：N<5 时只处理实际数量，标注"本机可处理对象受限，实际变化 X 个"及原因，并给出 K/候选数/N/成功数/跳过数；这走受限输入分支验收，但不能冒称已展示 5–10 个变化。N=0 记一次首批检查完成并显示无支持对象。不修改不支持类型补数量、不造对象、不再弹窗请用户批准已约定的"不足按实数"。
- **单项失败**：只尝试原对象，全INIT事务累计最多3次写入尝试（首次＋最多2次重试）；确认已删除、移动后身份不明或不可恢复时立即跳过；其余在第3次失败后自动标为跳过并给原因，无需等待玩家点击。核对不确定写入是否成功后才能判失败，不能遗漏已成功项。原目标及失败原因保留在摘要；以后对象条件改善时可进入正常DAILY候选，不重新开启INIT。除用户暂停或缺有效天气外，首批不会因等待“跳过”按钮而永不结束。
- **一次性**：重开、升级、保留用户数据的重装均不重复批量变化、不重发新手奖励。升级已有旧版进度迁移为已初始化，不重新发首批或奖励；不能因新增字段缺失把旧用户当新安装。
- **完成**：所有项成功或明确跳过才记完成，成功数与跳过数分别报告，不伪称全部成功。
- **报告口径**：首局摘要与最终报告分别记录 K、候选数、N、成功数、跳过数。

#### R4.2 DAILY（日常事件）

- **生效起点**：INIT 完成后的**下一自然日**起。
- **额度**：每个系统本地自然日全局至多一个对象推进一次——是"每天一个对象"，不是"每对象每天一次"。
- **动作**：选择一个已有受影响对象继续推进，或选一个干净对象引入效果；不补逐小时或逐日积欠。
- **候选过滤**：天气、免疫（R5）、可写/可恢复、状态上限。
- **抽取**：基准时间 = max(原始 mtime, 最近成功自然推进时间, 最近完整护理时间)，其中排除本程序写图标造成的 mtime；d 与 w 按第 2 节；候选按稳定对象 ID 排序后用已保存事件种子按 w 加权抽取。
- **缺席合并**：多天未启动（含三天）回来只合并补一次，与回归当日 DAILY 合并，总计至多一个对象一步。
- **去重**：当天重复打开、双开、唤醒或天气刷新不重复推进。
- **额度状态**：每个日期仅一个持久化事件记录，状态为pending（已占用唯一事件身份）、retryable（写入全失败但仍占用同一身份）、success（一次成功）、empty（无可推进）或init_occupied（由首批占用）。success/empty/init_occupied是当日终态；pending/retryable不等于成功，也不允许创建第二个事件。没有记录才可创建当天唯一记录。
- **重试**：同轮按保存的候选顺序最多尝试3个不同对象，最多一次成功。全部失败写为retryable，保留同一ID、种子、天气快照和尝试顺序；仅同日下次启动、天气定时检查或用户主动重试时继续有限尝试，天气刷新不能重抽计划，不后台紧密循环。跨日先核对旧pending/retryable的原生写入；确定未写入则关闭旧记录，不补债，再按新日期处理。若成功与否未明，先解决或恢复原值，不能直接换对象（刷新显示失败不等于属性写入失败）。
- **触发时机**：在线时，本地日期变更后的首次有效天气检查触发当日事件；复用现有调度/唤醒入口，不设高频轮询。跨午夜仍按R3快照年龄判断：允许使用前一日取得但仍有效的快照，不因跨日额外强制请求；事件记录与胶囊保留其真实快照时间。只有日期记录提供每日额度，天气快照不提供额度；任何超过24小时的快照都不能驱动新自然事件。
- **定时**：日历日期按系统本地日期，仅用于每日去重；240h 免疫按时间戳差计算，不按本地日期加十天。

#### R4.3 "在线"与"暂停"

- **在线**：程序进程正在运行为准，包括自启后在托盘运行；只关护理窗不算离线；胶囊隐藏不算离线。
- **暂停**：用户暂停是所有自然事件的最前置检查，期间不生成或续写 INIT/DAILY，不积欠；恢复时不追补暂停期间事件。
- **时钟回拨**：不得重新发放已消费日期的事件；免疫仍以持久化到期时间比较；测试只注入日期/时区/时钟，不改系统时间。

#### R4.4 单入口多条件时的唯一分支（按序匹配，不并行）

| 优先级 | 条件 | 唯一结果 |
|---|---|---|
| 1 | 用户暂停 | 不生成或续写 INIT/DAILY，不积欠 |
| 2 | INIT未结束且无有效天气 | 按R3显示等待，本轮有界；不执行INIT或DAILY |
| 3 | INIT尚未生成且有有效天气 | 生成固定K/N事务并执行；N=0也完成检查并占当天额度 |
| 4 | INIT正在执行且有有效天气 | 仅继续原事务，成功或自动跳过至完成；不发DAILY |
| 5 | INIT已完成，当日记录是success/empty/init_occupied | 当日终态，不创建或推进自然事件 |
| 6 | INIT已完成但无有效天气 | 不创建或续写DAILY，不积欠 |
| 7 | INIT已完成，有有效天气，当日记录为pending/retryable | 仅处理同一记录；成功→success，无候选→empty，全失败→retryable；不创建第二个事件 |
| 8 | INIT已完成，有有效天气，当日无记录 | 创建当天唯一记录为pending，按R4.2执行并转入success/empty/retryable |

INIT完成当天必有init_occupied，因此DAILY最早在下一自然日生效。缺席回归和断网恢复不具有独立事件类型，只是调用此入口的原因。暂停期间保留记录但不写入；暂停恢复当天是否推进仍受同一日期记录约束。

### R5 天气筛选、损伤状态与免疫

受潮、霉变、焦化都是图标画面的风格化表达，不表示真实文件烧毁或数据损坏。

**天气与权重表**（自上而下第一匹配项生效；湿度阈值 70 见第 2 节；权重为试玩配置，必须持久化实际抽取结果，不随刷新天气重抽）：

| 条件（WMO 分组按官方定义） | 受潮 / 霉变 / 焦化权重 |
|---|---|
| 降水/雷暴类 WMO {51,53,55,56,57,61,63,65,66,67,71,73,75,77,80,81,82,85,86,95,96,97,99} | RH≥70：85/15/0；否则 100/0/0 |
| 雾 WMO 45/48 | RH≥70：60/40/0；否则 100/0/0 |
| 其他天气且 RH≥70 | 40/60/0 |
| RH<70 且（WMO 0/1 或温度≥30°C） | 30/0/70 |
| 其余有效天气 | 90/0/10 |

**天气码集合**（按 2026-10-24 核对的 Open-Meteo 官方文档显式解析：https://open-meteo.com/en/docs ）：除上表降水集合外，支持 {0,1,2,3,45,48}。不得把通用 WMO 表中 68/69、79、87–90 等本接口未说明的码擅自补进生产映射。遇未知码、空字段或非数值数据 → 显示暂不可用，不生成新自然事件，已有状态与护理照常。接入时若官方契约变化，记录来源后最小更新映射并补测试。

这张表只是材质倾向，不是物理损坏模型；冻结为可配置表与测试，不临时改权重凑展示。干燥时霉变不在候选中。免疫过滤后剩余正权重重新归一化。

**强度**：轻/中/重沿认可资产强度分档，不用降低透明度制造"看不见的轻度"。首批强度与重度上限按第 2 节，达到上限后只在轻/中重抽；已有自然批次结果不重抽。DAILY 从干净进入轻度，其后每次只推进一级，不一夜从干净跳成全重度。

**损伤族**：每对象同时只保留一个主要损伤族；该族仍适配当天候选才可继续，否则跳过该对象。换族只在已清理或空闲状态发生，不叠满霉、水、焦三层。烧焦护理中保留"烟灰层/焦痕层"区分。

**菇**：损伤、护理进度和蘑菇实例独立存储。自然阶段为霉变轻→中→重→幼菇→成熟菇，仅当该对象获自然事件时前进一步，窗口外无逐帧生长模拟。首批重霉对象的菇状态按第2节抽取，不强制与天气冲突的菇。采摘只移除对应唯一ID的成熟菇并结算一次，不改变当前损伤或护理进度：先洗净再采菇仍然干净，先采菇再洗仍保留未清完的损伤。清洗不自动采菇、不删除既有菇。采摘后的再生仅在该对象仍是未清理的重霉、无菇且允许霉变推进时，下一次自然事件进入幼菇，再下次进入成熟；干净、其他损伤或防霉对象不因采摘重新长霉。其他损伤重度为满级，不再空推进。

**十天免疫**：完整清理过的对象 10 天内不再发霉，但可再次受潮、发焦。持久化 `lastCareCompletedAt` / `moldImmuneUntil`；本版对"十天"采用第 2 节的连续 240 小时默认，并在交付说明与验收记录中标注该换算；`t < moldImmuneUntil` 时霉变**硬排除**（不只是降权），`t ≥ moldImmuneUntil` 结束免疫并恢复天气候选。跨时区及夏令时仍按同一时间戳到期，不按本地日期重算。完整清理任一主要损伤均更新此窗口；只擦一部分、只采菇、练习样片、打开文件不算完整清理。清水渍后也不能绕过十天规则重新发霉。

**无可推进**：过滤后没有可变对象或相关状态全部满级时，不强造对象、不修改不支持类型；当天记"无可推进"，窗口说明，用户仍可护理与采摘。

### R6 护理窗口、首局、经济与收藏

**首局引导**（仅一次，可跳过）：城市设置 → 首批状态摘要 → 护理台练习 → 一次新手奖励。城市/天气等待不阻止跳过引导或进入练习。第一次点击“完成练习”或“跳过引导”时，以同一次存档操作记录引导完成、已奖励并增加24菇币；重开、重练、重复点击均不再发。随后提示可购买首件可见物品，购买是可选下一步，不是领取奖励或结束引导的前提。奖励不依赖联网，跳过后仍能从帮助重进；练习本身不反复产币。按天气没有成熟菇时，窗口内提供明确标为练习的成熟菇样片，不强造与天气冲突的真实桌面菇。

首批摘要按真实状态显示：未选地点→“选择城市后开始”；缺有效天气→“首批待天气”；执行中→“首批进行中（已结算x/N，成功s、跳过k）”；暂停→“已暂停，恢复后继续”；全部结算→“实际变化s个，跳过k个”并列原因。候选不足时按真实N完成受限分支，不错误地一直显示待天气；断网或未完成时不能显示空摘要或冒称完成。摘要是只读投影，不修改INIT状态、不消耗额度。

**窗口结构**：普通窗口合并护理台、收藏、小铺、设置。主区域只放当前对象，底部/侧边列真实受影响对象，今日变化和可采摘优先；列表不是多图标美术对照页。条目保留对象名称与原图辨认，可主动定位到 Explorer，不改变原生桌面选择语义。打开窗口保留上次对象；该对象已删除则回到有效对象。列表、采摘、小铺同步更新但不跳走当前护理对象。无受影响对象时给安静的"已收拾好"状态与可选练习入口，不造真实脏图标填列表。

**经济**（数值见第 2 节）：沿用现有库存/商城可复用实现，不继承旧高价/长等待曲线。大海绵使窗口擦洗范围增大约 30%，垫子立即换外观；基础护理工具开局可用。购买扣币/持有/应用/存档作为一次操作（原子），不能重复扣款、重复采同一菇或刷初始奖励。

**工具边界**（复用已完成资产与动作）：海绵可独立清霉；喷壶仅软化、刷子清理；擦水布独立去水，吸水纸点按、刮水器拖动、冷风按住持续生效；烟灰海绵点按吸灰、软毛刷扫灰，补色滚轮只复原图标焦痕。不得把工具拼成强制五步流程。除湿机/吸湿包先只展示状态，不自行加入自动经营或后台模拟。

**操作手感**：一次主要护理目标约 5–10 秒可见进展、正常操作 15 秒内完成；目标随窗口大小适配；接触立即有形状/位置匹配反馈；最后少量残渍自动收尾，不找最后一个像素。清理进度在松手/关窗/退出时可靠保存，重开继续。桌面仅在完整动作结束或松手后合并更新，不随每帧笔触刷新。工具在松手、失焦、切换对象、关窗时停止；风不得后台继续吹。

玩家正在护理的对象不被自然事件中途改写；延后至动作结束再检查该对象资格及最新状态版本，保留已清理区域。自然推进与护理都经过R4的同一写入协调器，不能用较旧的异步合成覆盖玩家刚完成的护理。

**快速处理**：次要入口，同样完成清理与十天免疫，但不自动采菇。

**采摘与收藏**：蘑菇独立层，采摘不自动洗净；不采不枯萎、不设背包压力。收藏保留品种、首次获得和来源对象的显示名称，重启一致。

**音效**：可关闭、默认克制，无持续环境音。

**视觉与布局复用**：优先复用 `previews/visual-assets-2026-10-24/care-table-demo/index.html` 中已认可的护理台、工具架、对象列表与四页层级，工具/反馈升级采用后续 `care-assets-v1` 和 `repair-tools-v1`，不另造后台管理面板。概念页中的 emoji、测试重置产币、强制先采菇再清洗、假桌面、固定今日次数仅是小样逻辑，不可移植为正式规则；本稿行为优先。

### R7 资产

资产根 `previews/visual-assets-2026-10-24/`：`material-effects-lab` 是认可的 12 种材质与颜色适配规则；`care-assets-v1` 提供蘑菇、工具、收纳、反馈；`repair-tools-v1` 提供新增工具与用途；`art-drafts` 是已认可文件夹风格；`mold-composite-demo` 为历史探索，不能覆盖后续认可方案。

原图从对象的真实图标资源提取，输入不含桌面背景、文字、选中框或烘焙的快捷方式箭头；箭头保留由Explorer原生绘制，不能重复叠加。native-icon-reference只作来源/适配参照，不把桌面截图当通用图标资产。

成熟菇加入生成的原生图标外观，让玩家看得出可采摘；窗口中用独立素材处理。采摘后只移除对应菇，其余外观按当前损伤与护理进度合成，不能重新补回已洗掉的霉斑。图标状态与随机布局固定缓存，按事件生成多尺寸 ICO；图标生成/窗口关闭后无持续绘制循环。

### R8 设置、退出、安装与兼容

**设置项**：城市、开机自启、胶囊显示/位置重置、暂停、音效、恢复全部图标、完全退出。自启默认关闭；开关反映系统实际状态，保存后下次登录只显示胶囊/托盘，不抢焦点、不重复新手引导；系统已禁用启动项时不显示假成功。

**两种"停"的区分**（不得混用）：

- **普通暂停**：只停止自然事件，保留当前外观。
- **恢复桌面并暂停**（按钮就使用此名称）：先停止/取消未落地写入，再还原原生外观、保留游戏进度，持久化为"已恢复外观且暂停自然变化"。此状态下手动护理可保存进度但不重新写桌面；退出、自启、天气刷新均不自动回显损伤。只有用户明确点"继续游戏"才恢复存档外观并重启后续日节奏，暂停期间不追补。此为作者默认，避免恢复后立即又被后台改回。

**退出**：先停止事件与工具、保存进度、恢复本程序修改的原图标，再结束进程。关闭窗口只回托盘，不恢复图标。异常退出至少在下次启动前置恢复遗留记录，再回显存档；不得覆盖玩家在程序运行期间自行选择的新图标。恢复前核对引用归属，未知/用户更改保留并报告（详见 R1）。

**交付与生命周期**：Windows x64 NSIS 当前用户安装包，复用现有 electron-builder，保留 portable 供可选调试，不用临时解压路径注册自启。升级保留设置/进度/INIT 完成标记；卸载复用同一恢复入口清理图标引用与自启，不留指向已删除缓存的图标。不自行发布 Release、不启用收费天气服务。打包产物本地提供路径与 SHA256。

## 5. 开发顺序、提交与 push

**0. 现状盘点**：记录当前大量未提交修改的归属与基线，备份需保护内容；不得 `git reset/clean/stash` 隐藏或提交无关用户改动。先确认现有分支可用，再决定必要隔离；只提交本 Goal 相关变更。

**1. 原生可行性阶段**：文件夹/快捷方式精确替换与恢复；小窗层级/玻璃/Win+D 专项原型（含实测记录）；天气源合法接入。组合不可行时给证据与最小替代供用户判断，不得默默换成覆盖层。

**2. 事件与规则阶段**：INIT 事务、天气映射、DAILY 单次、240h 免疫、存档迁移与原生回显。用可控时钟与注入天气跑规则测试。

**3. 体验阶段**：复用资产，接胶囊/托盘/自启、护理窗口、采摘收藏与最小商城；窗口状态与真实图标闭环。

**4. 交付阶段**：安装、升级、卸载、恢复、DPI、原生输入、性能验证，补证据与使用说明。

**提交纪律**：每阶段完成可验证纵向切片后运行 typecheck、相关测试与 build，确认无新回归再做小提交并 push `origin experience/visual-playground`，记录 commit 与已完成/未完成；不要等全部结束才 push，也不要 push 明知会破坏既有路径的半成品。**每次 push 后用 `git ls-remote` 或 fetch 校验远端确含该提交**；无网络/无权限时保留本地提交、记录失败原因与重试结果，继续可独立工作；未验证远端提交实际存在前，不得宣称已推送或完成远端交付。

最终执行 `npm test`、`npm run build`、`npm run dist:win`（含安装目标）、相关原生 UAT；修改指南时跑 `qa:dox`。旧验收与本 Goal 冲突的测试按新行为修改，不能删掉全部测试凑绿。不强推、不自行合并主分支、不上传缓存/依赖/凭证/用户桌面内容、不未经要求发布安装包。源码、版本化资产、使用文档、复用台账、验收证据与变更说明推远端。

## 7. 完成与阻塞判定

**完成口径**：工程交付就绪要求A01–A24中所有技术项PASS、安装包有本地路径与SHA256、各阶段提交已验证在远端。用户视觉尚未确认时只能报告“工程交付就绪，待用户视觉验收”；收到该确认后才可报告完整验收完成。任何必需技术项FAIL或NOT TESTED都表示尚未完成，不以原因说明代替通过。确需降级时，先取得用户对具体变更的明确决定，更新对应规则和验收预期，再实际重测通过，不能把批准降级直接写为PASS。最终报告列明交付包、支持类型、实际复用来源、全部验收状态与证据、性能实测条件与结果、最后推送提交及待确认内容；不得把完成编码或评审高分写成完整用户验收。

**阻塞判定**（满足任一条即暂停该支路并向用户报告，同时继续可独立推进的工作）：

1. 硬要求技术上无法实现，或需改变交付用途/分发方式；
2. 原生图标替换或恢复在必交类型上整体不通；
3. R2 的层级/材质/Win+D 组合无法兼得，需用户裁决降级方案；
4. 天气接口对既定用途受限且无已授权替代。

报告格式固定为：**证据 → 最小调整方案 → 影响范围 → 待用户裁决点**。不得静默放弃核心体验、不得默默替换为覆盖层、不得把待确认项记为PASS。单对象异常可按R1/R4处理；测试机上的必需体验失败仍记FAIL，不能用“单台机器失败”豁免本次验收。等待裁决时继续可独立推进的工作。
