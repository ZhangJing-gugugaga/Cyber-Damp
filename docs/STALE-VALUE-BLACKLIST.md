# 旧口径残留黑名单（STALE-VALUE-BLACKLIST）

| 项 | 内容 |
| --- | --- |
| 版本 | v1.0（2026-10-17） |
| 维护方 | 架构侧主笔，设计侧共编；pattern 增补须双方知情 |
| 配套脚本 | `docs/scripts/scan-stale-values.mjs`（唯一真相源，本文不内联副本——防双源漂移） |
| 适用范围 | 全仓库文档与源码（自动发现，新增文件自动纳入；PRD.md v1.0 历史存档除外） |

## 1. 为什么有这份文件

项目已有两层质量防线，本文件补第三层、且不与前两层重叠：

| 防线 | 管什么 | 谁跑 |
| --- | --- | --- |
| P0 复检（emoji/渐变/JSON 合法/禁止条款） | 底线合规 | 双方每轮文档定稿 |
| 构建门（tsc/lint/单文件 300 行） | 代码质量 | 前端 CI |
| **本黑名单** | **口径漂移——旧数值/旧公式/旧单位被新约束取代后残留在文档里** | 双方每轮文档 v+1 后各跑一次 |

立项根因（双方各踩一次的同款病）：
- 架构侧：增量添加硬约束时未回头修订被取代的旧段落（`Body.setMass(sizeToMass)` 线性样例与 sag 线性参考式各留了一轮）。
- 设计侧：版本 bump 未跑残留扫描（sag k=1.46 早期值就是这么抓到的）。
- 共同教训：**"我方以为对方会抓到"的交叉缝**——单边扫描漏掉的，往往是只在对方文档里成立、在本方文档里失效的交叉口径。

## 2. 阻塞级 pattern（命中 = 真残留，必修；除非人工判定为历史标注）

| pattern | 被什么取代 | 来源侧 |
| --- | --- | --- |
| `\b1\.46\b` | sag 定标 k≈3.5 | 双方 |
| `\b5\.20\b` | 1GB→5.22（二进制 KB 口径，5.20 系十进制粗算） | 双方 |
| `\b5\.80\b` | 5GB→5.78 | 设计侧 |
| `\b6\.28\b` | 25GB→6.33 | 设计侧 |
| `6GB` / `承重 6` / `(?<!\d)6\/25(?!\d)` | 字节承重 5GB / 25GB / ≥100GB（崩断按字节判） | 双方 |
| `log10\(bytes` | sag 参考式改用 sizeToMass 表达 | 双方 |
| `mass:\s*0\.02` | 绳链 0.5/链（总 7.0） | 架构侧 |
| `\b35:1\b` | 单挂点质量比 ≤40:1（包络内最坏约 27） | 架构侧 |
| `\b9\.8\b` | 24GB→6.32（sizeToMass 实算锚点） | 架构侧 |

注：`6\/25` 带数字边界防日期格式误命中（如 2026/6/25）；数值 pattern 均带 `\b` 防 15.20/19.8 类子串误命中。

## 3. 非阻塞级 + 豁免规则（命中须人工三分类，不自动判失败）

| pattern | 说明 |
| --- | --- |
| `40-60` | **早期 PRNG 文件数方案，现行方案是 16 个命名锚文件（SPEC 锁定，封闭 pin 集不扩展）**。仅"取代本档早期 X 方案"式历史标注可保留；任何把 40-60 当作现行文件数的表述都是真残留（布局密度、网格规格会全错） |
| `linear-gradient` / `radial-gradient` / `conic-gradient` | P0-2 禁渐变；全项目规则，不限绳索线 |
| `[\u{1F300}-\u{1F9FF}\u{2600}-\u{26FF}\u{2700}-\u{27BF}\u{1FA00}-\u{1FAFF}]` | P0-1 禁 emoji 功能图标；emoji 检测为尽力而为，以人工 P0 复检为准 |
| `lorem ipsum` / `welcome to` / `sign up today`（i） | P0-3 禁 AI 模板文案；**豁免场景**：双方文档的禁止条款里合法出现这些词（规则陈述本身），命中后须确认是否位于禁止条款上下文，不能一律判失败 |

**豁免标记机制（行级，自文档化）**：命中行经人工判定为豁免后，在行尾加 `<!-- stale-scan:exempt 原因 -->`（代码文件用 `// stale-scan:exempt 原因`），扫描器跳过该行。三类标准豁免：历史标注（"取代本档早期 X"上下文）、禁止条款/防呆负提及（如"禁写 5.20"、"禁止 Welcome to"）、以及其他需向后续读者说明为何保留的命中。标记必须带原因——无原因标记视为未分类。

## 4. 扫描脚本与用法

```bash
node docs/scripts/scan-stale-values.mjs
```

- 扫描范围：自动发现全仓库 `.md/.css/.json/.ts/.tsx/.js/.mjs/.cjs`（跳过 node_modules/.git/dist/build/logs/.claude/.workbuddy；PRD.md v1.0 历史存档、package.json、tsconfig*.json、package-lock.json、本黑名单文档与扫描器自身除外——后两者合法包含全部 pattern）。
- 行级豁免：命中行含 `stale-scan:exempt` 标记即跳过（见第 3 节）。
- 输出：`文件:行号 [阻塞|非阻塞] pattern → 替代值 :: 命中文本`，末尾汇总计数。
- 退出码恒 0——扫描器只负责发现，**分类与处置永远是人做的**。
- 脚本是唯一真相源：改 pattern 只改 `docs/scripts/scan-stale-values.mjs` 并同步本文第 2/3 节的表，不在此内联第二份代码。

## 5. 运行纪律

1. **时机**：任何文档 v+1 定稿后、回传前，归口方各跑一次（架构侧跑全量，设计侧跑全量，互不代替）。
2. **三分类**：每个命中判为——真残留（当轮必修）/ 历史标注（保留，须带"取代本档早期 X"上下文）/ 禁止条款陈述（豁免）。
3. **留痕**：分类结果写进各自文档的变更记录行（如"残留扫描：阻塞 0 / 非阻塞 3（2 历史标注 + 1 豁免）"）。
4. **新漂移入库**：任何一轮发现的、此前未列入的新旧口径对，当轮补进第 2/3 节并同步对方——黑名单随项目教训增长。
