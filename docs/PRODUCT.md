# 当前产品规格

本文件汇总仍有效的原生桌面产品规则及最新用户决定，区分目标要求与实际完成状态。实现缺口见 [CURRENT-STATUS.md](CURRENT-STATUS.md)，验收见 [CARE-DESKTOP-UAT.md](CARE-DESKTOP-UAT.md)。旧日期规格、阶段报告和旧设计已退出最新文件树，不再作为并行权威。

## 产品边界

- Windows x64 可安装轻量桌面玩具；真实天气驱动少量原生文件夹/普通快捷方式图标变化，护理和采摘在普通窗口内进行。
- 原生单击、双击、右键、框选、拖放、键盘交互完整保留；不建立全屏覆盖层，不隐藏/替代/重排原生图标，不钩取/转发桌面输入。
- 少量原生图标受潮/发霉/发焦，玩家可轻量护理、独立采菇、收藏与购买小道具；不增加强制护理、复杂经营、过期或背包压力。
- 首批正常候选足量时5–10个最久未动对象，后续全局每天至多3个对象各一步（回南天警报期间至多5个）；缺席多天只补一次，不增加每日任务。
- 可选静态壁纸效果（R9）：玩家主动开启后，把天气雾气/水痕/墙角霉斑合成到原壁纸的副本上；不挂接 WorkerW、不做动态壁纸，退出恢复原值。
- 胶囊为中上方天气小窗，普通应用优先；Win+D 可隐藏，托盘可唤回。关闭护理窗回托盘，完全退出恢复引用并保留进度。自启默认关闭。
- 默认长沙、明确标识的离线默认快照、省市选择保留。真实天气、缓存和默认数据不能混称实况。
- 当前只保留原生产品；旧覆盖层、绳索/替身/旧图集及其环境开关和旧测试已彻底退役，不能以复用为由重新接回。
- 用户最新明确决定优先；参数表其余数值为已收敛的试玩默认，不以实现缺陷改写产品目标。构建通过不等于用户验收通过。

## R0 复用与数据保护

修改前检查现有模块和官方/许可适配实现，记录来源，成熟能力只做必要适配；不为统一风格更换整套实现。Shell枚举/后台图标提取、ICO封装、事件协调、原子存档、素材和普通窗口继续复用。仅图标引用可按 R1 修改，真实文档内容、名称与位置不能修改；不读取文件正文或认证文件来建立索引。源代码只在 src/ 修改，构建生成 dist，不直接修补产物。

## 行为规则

### R1 原生图标替换与恢复

**支持范围**：仅文件夹与普通 `.lnk`。快捷方式仅 update 图标引用，目标、参数、工作目录、原生箭头等行为保持不变；文件夹仅修改必要图标配置，保留 `desktop.ini` 其他内容、原图标及必要原属性。原生文件夹属性在 Explorer 其他位置也会反映，不伪称"仅桌面变化"。

**禁止项**：改系统 DLL、全局文件类型关联、对象位置/名称/内容；新建快捷方式代替原对象；杀 Explorer、重建全局图标缓存、要求用户重启才能显示效果。

**写前落盘**：原始引用与恢复信息在修改前可靠落盘；原生刷新只针对必要对象。

**失败处理**：按R4执行有限重试或明确跳过，单个失败不阻塞其余可处理对象，在护理窗口给出简短原因；必交类型整体不通则报告阻塞，不得用替身绕过验收。

**恢复语义**：恢复的是用户原值，不是系统默认。恢复前核对当前引用归属；若已被用户自行更改，保留用户值并报告。删除/移动对象后不复活、不覆盖新同名对象；可可靠识别同一对象的改名则保留游戏状态，否则停止修改并说明。链接损坏、公用桌面无写权限等跳过而不阻塞其他对象，不要求全局管理员运行。

### R2 天气胶囊窗口

有界小窗口，绝非全屏幕布。可拖动并记住位置；重置布局回顶部中央；显示器拔插/DPI 变化后夹回可见工作区；不强移桌面图标，不建立覆盖全屏的透明宿主。

可见胶囊区域外不截获桌面点击，包括窗口透明留白；点击与拖动沿用系统拖动阈值区分，拖动结束不误打开护理窗口。

默认不压住普通应用、不抢焦点；全屏应用期间隐藏；不持续呼吸、闪烁或展开。点击胶囊打开护理台；右键提供隐藏、设置、退出。隐藏只隐藏胶囊，不暂停日推进，托盘始终是备用入口。

全屏/覆盖检测复用 `src/main/native/win32-foreground.ts` 的 SetWinEventHook 与现有窗口几何，按显示器和 DPI 核对；不得用输入钩取或全屏宿主替代。玻璃优先复用现有 Win32 材质，系统不支持时诚实半透明降级，不模糊文字冒充背景玻璃。

**已接受的层级决定**：优先不干扰原生桌面、不压普通应用、不抢焦点。允许 Win+D 后胶囊隐藏，由托盘或程序入口唤回；此决定不再作为待裁决问题，也不等于相关行为已通过真机验收。

### R3 天气、城市与离线

室外天气参考取所选城市最新 `current` 的温度、相对湿度、WMO 天气码及快照时间，不是全天最高/最低温，不冒充室内传感器或精确定位。

**有效默认策略**：未选城市采用明确标注的默认长沙；省市级联选择复用 china-division，坐标解析复用既有服务。实况与可用缓存均不可得时允许内置默认快照维持开箱/离线体验，界面必须标注“内置默认”，不得当作真实当前天气。默认地点/快照定义在 `src/shared/native-defaults.ts`；保留该已接受增量，不恢复旧版强制联网/选城门槛。

有用户选择的地点时，新城市与其天气状态保持一致；切换失败保留原城市/缓存并可重试。搜索失败不随机冒选地点，不重置已有护理。普通缓存30分钟、单请求8秒、首次最多两次重试（间隔1秒/3秒，最坏28秒）。有缓存而断网显示快照时间与离线状态；24小时外的普通缓存不得驱动新自然事件。内置默认与真实缓存明确区分。普通快照年龄按气象快照时间核对，不能通过刷新获取时间使过期数据永久有效。

启动、唤醒、改城和缓存检查复用主进程天气服务，不逐帧联网。改城/刷新不能额外获得日额度或重抽已落地状态；不可用/未知码不伪造实况。默认天气也是明确标识的降级，不能拿它代替实网接入验收。后台重试有界，等待网络不遮挡原生桌面、不阻止护理/收藏/小铺。

Open-Meteo 数据署名在设置页及胶囊提示可见。当前用途限本机与私下非商业体验；不得自行公开发布安装包、宣传或接入收费服务。未来用途变化再核对授权。

### R4 自然事件模型（权威定义）

自然事件只有两种，**同一时刻互斥**：`INIT`（一次性首局事务）与 `DAILY`（日常推进）。此外一切（外观回显、手动护理、退出恢复原图、首批摘要展示）都**不是**自然事件，不计额度、不消耗当日额度、不参与互斥判断。

所有原生写入仍由同一协调器串行管理：写前保存事件/对象/目标状态版本和恢复信息；同一对象的自然变化、护理、回显和恢复不能互相覆盖，过期合成结果不得落地。启动先核对未结算写入再调度新事件；已写成功而回执未存时，只补结算，不再推进。若跨午夜时无法确定成功日期，保守占用写入意图日及核对日的额度并报告，不在核对日再发第二个自然事件。INIT待处理对象暂不进入可护理列表；已成功项可正常护理，续作不覆盖它们。

#### R4.1 INIT（首局事务）

- **生成条件**：首次安装，有选定或明确标记的默认城市，且取得按 R3 可用于事件的天气。界面与原生桌面不等天气请求即可用。
- **目标集合**：一次抽取 K（参数表）；从真实 Shell 可见且支持、可写、可恢复的对象中，按原始 mtime 从旧到新取前 N=min(K, 可写且可恢复候选数)，mtime 相同按稳定对象 ID 排序。用 mtime 近似"最久未动"，不声称可靠得知"最久未打开"，不扫描文档内容、不递归计算目录体积。
- **固定性**：N 个目标、天气快照、随机状态与随机布局在事务建立时固定并持久化；**全生命周期不变**，每个对象至多成功一次。
- **执行跨度**：允许首个有效自然日批量完成；也允许崩溃重试或跨日续作日完成剩余**全部**对象，总数仍为 N。不得把 INIT 改成"每天只处理一个"，不得另抽一批，不得重抽天气/状态，不得扩大目标集合。
- **占用额度**：每个实际写入日与最终完成日各占用该自然日的唯一普通日额度；这些日子不再发 DAILY。INIT 未结束前不并行发 DAILY。
- **候选不足**：N<5 时只处理实际数量，标注"本机可处理对象受限，实际变化 X 个"及原因，并给出 K/候选数/N/成功数/跳过数；这走受限输入分支验收，但不能冒称已展示 5–10 个变化。N=0 记一次首批检查完成并显示无支持对象。不修改不支持类型补数量、不造对象、不再弹窗请用户批准已约定的"不足按实数"。
- **单项失败**：只尝试原对象，全INIT事务累计最多3次写入尝试（首次＋最多2次重试）；确认已删除、移动后身份不明或不可恢复时立即跳过；其余在第3次失败后自动标为跳过并给原因，无需等待玩家点击。核对不确定写入是否成功后才能判失败，不能遗漏已成功项。原目标及失败原因保留在摘要；以后对象条件改善时可进入正常DAILY候选，不重新开启INIT。除用户暂停或缺有效天气外，首批不会因等待“跳过”按钮而永不结束。
- **一次性**：重开、升级、保留用户数据的重装均不重复批量变化、不重发新手奖励。升级已有旧版进度迁移为已初始化，不重新发首批或奖励；不能因新增字段缺失把旧用户当新安装。
- **完成**：所有项成功或明确跳过才记完成，成功数与跳过数分别报告，不伪称全部成功。
- **报告口径**：首局摘要与最终报告分别记录 K、候选数、N、成功数、跳过数。

#### R4.2 DAILY（日常事件）

- **生效起点**：INIT 完成后的**下一自然日**起。
- **额度**（v0.2）：每个系统本地自然日全局至多3个对象各推进一次，回南天警报期间至多5个；每个对象每天至多一步。额度在当日记录建立时固定，之后的天气刷新不改变。玩家播种、相邻蔓延与自然推进共用这一额度，不额外加速。
- **动作**：每个槽位选择一个已有受影响对象继续推进，或选一个干净对象引入效果；不补逐小时或逐日积欠。同一日记录内的槽位按保存的候选顺序依次结算，每个槽位最多尝试3个不同对象。
- **候选过滤**：天气、免疫（R5）、可写/可恢复、状态上限。
- **抽取**：基准时间 = max(原始 mtime, 最近成功自然推进时间, 最近完整护理时间)，其中排除本程序写图标造成的 mtime；d 与 w 按参数表；候选按稳定对象 ID 排序后用已保存事件种子按 w 加权抽取。
- **缺席合并**：多天未启动（含三天）回来只合并补一次，与回归当日 DAILY 合并，总计至多一个对象一步。
- **去重**：当天重复打开、双开、唤醒或天气刷新不重复推进。
- **额度状态**：每个日期仅一个持久化事件记录（v0.2 内含至多额度个槽位，见 [玩法契约](contracts/gameplay-v2.md)），状态为pending（已占用唯一事件身份）、retryable（写入全失败但仍占用同一身份）、success（一次成功）、empty（无可推进）或init_occupied（由首批占用）。success/empty/init_occupied是当日终态；pending/retryable不等于成功，也不允许创建第二个事件。没有记录才可创建当天唯一记录。
- **重试**：同轮按保存的候选顺序最多尝试3个不同对象，最多一次成功。全部失败写为retryable，保留同一ID、种子、天气快照和尝试顺序；仅同日下次启动、天气定时检查或用户主动重试时继续有限尝试，天气刷新不能重抽计划，不后台紧密循环。跨日先核对旧pending/retryable的原生写入；确定未写入则关闭旧记录，不补债，再按新日期处理。若成功与否未明，先解决或恢复原值，不能直接换对象（刷新显示失败不等于属性写入失败）。
- **触发时机**：在线时，本地日期变更后的首次有效天气检查触发当日事件；复用现有调度/唤醒入口，不设高频轮询。跨午夜仍按R3快照年龄判断：允许使用前一日取得但仍有效的快照，不因跨日额外强制请求；事件记录与胶囊保留其真实快照时间。只有日期记录提供每日额度，天气快照不提供额度；任何超过24小时的快照都不能驱动新自然事件。
- **定时**：日历日期按系统本地日期，仅用于每日去重；240h 免疫按时间戳差计算，不按本地日期加十天。

#### R4.3 "在线"与"暂停"

- **在线**：程序进程正在运行为准，包括自启后在托盘运行；只关护理窗不算离线；胶囊隐藏不算离线。
- **暂停**：用户暂停是所有自然事件的最前置检查，期间不生成或续写 INIT/DAILY，不积欠；恢复时不追补暂停期间事件。
- **时钟回拨**：不得重新发放已消费日期的事件；免疫仍以持久化到期时间比较；测试只注入日期/时区/时钟，不改系统时间。

#### R4.4 单入口多条件时的唯一分支（按序匹配，不并行）

| 优先级 | 条件 | 唯一结果 |
|---|---|---|
| 1 | 用户暂停 | 不生成或续写 INIT/DAILY，不积欠 |
| 2 | INIT未结束且无有效天气 | 按R3显示等待，本轮有界；不执行INIT或DAILY |
| 3 | INIT尚未生成且有有效天气 | 生成固定K/N事务并执行；N=0也完成检查并占当天额度 |
| 4 | INIT正在执行且有有效天气 | 仅继续原事务，成功或自动跳过至完成；不发DAILY |
| 5 | INIT已完成，当日记录是success/empty/init_occupied | 当日终态，不创建或推进自然事件 |
| 6 | INIT已完成但无有效天气 | 不创建或续写DAILY，不积欠 |
| 7 | INIT已完成，有有效天气，当日记录为pending/retryable | 仅处理同一记录；成功→success，无候选→empty，全失败→retryable；不创建第二个事件 |
| 8 | INIT已完成，有有效天气，当日无记录 | 创建当天唯一记录为pending，按R4.2执行并转入success/empty/retryable |

INIT完成当天必有init_occupied，因此DAILY最早在下一自然日生效。缺席回归和断网恢复不具有独立事件类型，只是调用此入口的原因。暂停期间保留记录但不写入；暂停恢复当天是否推进仍受同一日期记录约束。

### R5 天气筛选、损伤状态与免疫

受潮、霉变、焦化都是图标画面的风格化表达，不表示真实文件烧毁或数据损坏。

**天气与权重表**（自上而下第一匹配项生效；湿度阈值 70 见参数表；权重为试玩配置，必须持久化实际抽取结果，不随刷新天气重抽）：

| 条件（WMO 分组按官方定义） | 受潮 / 霉变 / 焦化权重 |
|---|---|
| 降水/雷暴类 WMO {51,53,55,56,57,61,63,65,66,67,71,73,75,77,80,81,82,85,86,95,96,97,99} | RH≥70：85/15/0；否则 100/0/0 |
| 雾 WMO 45/48 | RH≥70：60/40/0；否则 100/0/0 |
| 其他天气且 RH≥70 | 40/60/0 |
| RH<70 且（WMO 0/1 或温度≥30°C） | 30/0/70 |
| 其余有效天气 | 90/0/10 |

**天气码集合**（按 2026-10-24 核对的 Open-Meteo 官方文档显式解析：https://open-meteo.com/en/docs ）：除上表降水集合外，支持 {0,1,2,3,45,48}。不得把通用 WMO 表中 68/69、79、87–90 等本接口未说明的码擅自补进生产映射。遇未知码、空字段或非数值数据 → 显示暂不可用，不生成新自然事件，已有状态与护理照常。接入时若官方契约变化，记录来源后最小更新映射并补测试。

这张表只是材质倾向，不是物理损坏模型；冻结为可配置表与测试，不临时改权重凑展示。干燥时霉变不在候选中。免疫过滤后剩余正权重重新归一化。

**强度**：轻/中/重沿认可资产强度分档，不用降低透明度制造"看不见的轻度"。首批强度与重度上限按参数表，达到上限后只在轻/中重抽；已有自然批次结果不重抽。DAILY 从干净进入轻度，其后每次只推进一级，不一夜从干净跳成全重度。

**损伤族**：每对象同时只保留一个主要损伤族；该族仍适配当天候选才可继续，否则跳过该对象。换族只在已清理或空闲状态发生，不叠满霉、水、焦三层。烧焦护理中保留"烟灰层/焦痕层"区分。

**菇**：损伤、护理进度和蘑菇实例独立存储。自然阶段为霉变轻→中→重→幼菇→成熟菇，仅当该对象获自然事件时前进一步，窗口外无逐帧生长模拟。首批重霉对象的菇状态按参数表抽取，不强制与天气冲突的菇。采摘只移除对应唯一ID的成熟菇并结算一次，不改变当前损伤或护理进度：先洗净再采菇仍然干净，先采菇再洗仍保留未清完的损伤。清洗不自动采菇、不删除既有菇。采摘后的再生仅在该对象仍是未清理的重霉、无菇且允许霉变推进时，下一次自然事件进入幼菇，再下次进入成熟；干净、其他损伤或防霉对象不因采摘重新长霉。其他损伤重度为满级，不再空推进。

**十天免疫**：完整清理过的对象 10 天内不再发霉，但可再次受潮、发焦。持久化 `lastCareCompletedAt` / `moldImmuneUntil`；本版对"十天"采用参数表的连续 240 小时默认，并在交付说明与验收记录中标注该换算；`t < moldImmuneUntil` 时霉变**硬排除**（不只是降权），`t ≥ moldImmuneUntil` 结束免疫并恢复天气候选。跨时区及夏令时仍按同一时间戳到期，不按本地日期重算。完整清理任一主要损伤均更新此窗口；只擦一部分、只采菇、练习样片、打开文件不算完整清理。清水渍后也不能绕过十天规则重新发霉。

**无可推进**：过滤后没有可变对象或相关状态全部满级时，不强造对象、不修改不支持类型；当天记"无可推进"，窗口说明，用户仍可护理与采摘。

#### R5.1 品种（v0.2）

13 款新品种对应美术资产 01–13，ID 见 [玩法契约](contracts/gameplay-v2.md)。幼菇出现时确定品种，之后不随天气重抽。判定输入：对象类别、有效快照的天气码/湿度/温度、本地时段、警报状态和存档种子。玩家播种的品种优先。类别只看对象种类和 `.lnk` 目标元数据（`src/shared/object-category.ts`），不读文件正文。雨神之冠只在警报期出现。旧品种 oyster/enoki/shy/bolete/lava 的收藏记录原样保留为"早期品种"，新事件不再产生旧品种。权重表是试玩配置，冻结为可测表。

#### R5.2 相邻蔓延（v0.2）

相邻关系由 Shell 只读读取的真实图标坐标计算，不移动、不重排图标。只有未清理的重度霉变对象可以在自然事件中把霉传给相邻且符合天气条件的干净对象；防霉期内的对象硬排除。蔓延占用日额度槽位，结果按事件种子固定并持久化。删除或移动的对象不复活，也不参与蔓延。

#### R5.3 回南天警报（v0.2）

触发条件见参数表；未知码或默认天气不触发警报。警报状态持久化，同一快照反复刷新不累加降水次数，时钟回拨不重复开启已结束的警报。警报期间额度提高到5，开放雨神之冠，壁纸效果（若已开启）加重。警报结束不清除已有状态。警报不是任务，不要求玩家在警报期完成任何事。

### R6 护理窗口、首局、经济与收藏

**首局引导**（仅一次，可跳过）：城市设置 → 首批状态摘要 → 护理台练习 → 一次新手奖励。城市/天气等待不阻止跳过引导或进入练习。第一次点击“完成练习”或“跳过引导”时，以同一次存档操作记录引导完成、已奖励并增加24菇币；重开、重练、重复点击均不再发。随后提示可购买首件可见物品，购买是可选下一步，不是领取奖励或结束引导的前提。奖励不依赖联网，跳过后仍能从帮助重进；练习本身不反复产币。按天气没有成熟菇时，窗口内提供明确标为练习的成熟菇样片，不强造与天气冲突的真实桌面菇。

首批摘要按真实状态显示：未选地点→明确显示默认长沙及天气来源；缺有效天气→“首批待天气”；执行中→“首批进行中（已结算x/N，成功s、跳过k）”；暂停→“已暂停，恢复后继续”；全部结算→“实际变化s个，跳过k个”并列原因。候选不足时按真实N完成受限分支，不错误地一直显示待天气；断网或未完成时不能显示空摘要或冒称完成。摘要是只读投影，不修改INIT状态、不消耗额度。

**窗口结构**：普通窗口合并护理台、收藏、小铺、设置。主区域只放当前对象，底部/侧边列真实受影响对象，今日变化和可采摘优先；列表不是多图标美术对照页。条目保留对象名称与原图辨认，可主动定位到 Explorer，不改变原生桌面选择语义。打开窗口保留上次对象；该对象已删除则回到有效对象。列表、采摘、小铺同步更新但不跳走当前护理对象。无受影响对象时给安静的"已收拾好"状态与可选练习入口，不造真实脏图标填列表。

**经济**（数值见参数表）：沿用现有库存/商城可复用实现，不继承旧高价/长等待曲线。大海绵使窗口擦洗范围增大约 30%，垫子立即换外观；基础护理工具开局可用。购买扣币/持有/应用/存档作为一次操作（原子），不能重复扣款、重复采同一菇或刷初始奖励。

**工具边界**（复用已完成资产与动作）：海绵可独立清霉；喷壶仅软化、刷子清理；擦水布独立去水，吸水纸点按、刮水器拖动、冷风按住持续生效；烟灰海绵点按吸灰、软毛刷扫灰，补色滚轮只复原图标焦痕。不得把工具拼成强制五步流程。除湿机/吸湿包先只展示状态，不自行加入自动经营或后台模拟。

**护理 2.0 分层**（v0.2）：受潮分水珠层与水膜层，霉变为霉斑层（喷壶写软化状态，软化区域刷洗更快），焦化分烟灰层与焦痕层（补色滚轮只作用于已露出的焦痕）。轻度只有上层，中/重度有全部层。万能海绵对所有层生效，效率见参数表，保证不强制流程。每层独立保存掩码（与 care-mask 同一编码）；v0.1 单层掩码迁移为对应族的上层。可按住空格高亮剩余损伤，高亮不清除任何东西。精细护理奖励见参数表；快速处理照样完成清理与防霉，但不发精细奖励。剪刀采摘按 cutQuality 结算孢子，剪歪也能正常采到菇。完成护理时有光泽扫过、提示音（可关）与列表更新；对象留言为纯文本，按类别和品种选取，不读文件正文。

**操作手感**：一次主要护理目标约 5–10 秒可见进展、正常操作按参数表时长完成；目标随窗口大小适配；接触立即有形状/位置匹配反馈；最后少量残渍自动收尾，不找最后一个像素。清理进度在松手/关窗/退出时可靠保存，重开继续。桌面仅在完整动作结束或松手后合并更新，不随每帧笔触刷新。工具在松手、失焦、切换对象、关窗时停止；风不得后台继续吹。

玩家正在护理的对象不被自然事件中途改写；延后至动作结束再检查该对象资格及最新状态版本，保留已清理区域。自然推进与护理都经过R4的同一写入协调器，不能用较旧的异步合成覆盖玩家刚完成的护理。

**快速处理**：次要入口，同样完成清理与十天免疫，但不自动采菇。

**采摘与收藏**：蘑菇独立层，采摘不自动洗净；不采不枯萎、不设背包压力。收藏保留品种、首次获得和来源对象的显示名称，重启一致。

**音效**：可关闭、默认克制，无持续环境音。

**视觉与布局复用**：复用现行 care.html/care.css/care.ts 的四页层级、对象列表与护理台，素材及工具作者源继续使用 care-assets-v1 / repair-tools-v1。作者预览不是产品；其测试重置、假桌面、固定次数等不移植为正式规则。

### R8 设置、退出、安装与兼容

**设置项**：城市、开机自启、胶囊显示/位置重置、暂停、音效、恢复全部图标、完全退出。自启默认关闭；开关反映系统实际状态，保存后下次登录只显示胶囊/托盘，不抢焦点、不重复新手引导；系统已禁用启动项时不显示假成功。

**两种"停"的区分**（不得混用）：

- **普通暂停**：只停止自然事件，保留当前外观。
- **恢复桌面并暂停**（按钮就使用此名称）：先停止/取消未落地写入，再还原原生外观、保留游戏进度，持久化为"已恢复外观且暂停自然变化"。此状态下手动护理可保存进度但不重新写桌面；退出、自启、天气刷新均不自动回显损伤。只有用户明确点"继续游戏"才恢复存档外观并重启后续日节奏，暂停期间不追补。此为作者默认，避免恢复后立即又被后台改回。

**退出**：先停止事件与工具、保存进度、恢复本程序修改的原图标，再结束进程。关闭窗口只回托盘，不恢复图标。异常退出至少在下次启动前置恢复遗留记录，再回显存档；不得覆盖玩家在程序运行期间自行选择的新图标。恢复前核对引用归属，未知/用户更改保留并报告（详见 R1）。

**设置项增补（v0.2）**：壁纸效果开关（默认关闭）、菇合成版本 A/B（实测选定后可移除）。

**交付与生命周期**：Windows x64 NSIS 当前用户安装包，复用现有 electron-builder，保留 portable 供可选调试，不用临时解压路径注册自启。升级保留设置/进度/INIT 完成标记；卸载复用同一恢复入口清理图标引用与自启，不留指向已删除缓存的图标。不自行发布 Release、不启用收费天气服务。打包产物本地提供路径与 SHA256。

### R9 静态壁纸效果（v0.2）

**开启**：默认关闭；引导中或设置页由玩家主动开启。开启即授权读取当前壁纸图片的像素，用来生成效果副本。原壁纸文件不改动。

**合成**：原壁纸像素与天气效果层（雾层随湿度单调增强、降水码出现水痕、墙角霉斑0–3档只在警报期增长）合成为静态图片，存放在 `%APPDATA%/cyber-damp/wallpaper/`，再设为当前用户壁纸。合成在天气变化、警报变化或墙面擦拭提交时进行，每天次数有限，不逐帧设置，也不常驻绘制循环。晴天或低湿时雾层逐步减退。纯像素实现位于 `src/shared/wallpaper/`，与护理台墙面页共用。

**墙面页**：护理台新增墙面页，用刮水器擦雾，擦雾掩码按 care-mask 编码保存。松手或确认时才提交，主进程限频合成。擦雾不计日额度，也不产菇币。

**写前登记与恢复**：首次设置前，把原壁纸路径、`WallpaperStyle`、`TileWallpaper` 可靠落盘到独立的恢复登记（不在游戏存档内）。完全退出、关闭壁纸效果、"恢复桌面并暂停"和卸载时恢复原值。异常退出后下次启动先恢复。恢复前核对当前壁纸是否仍是本程序的合成图；若用户已自行更换，保留用户的壁纸，停用效果并说明，不覆盖。

**跳过条件**：检测到幻灯片放映、Windows 聚焦、纯色背景、壁纸文件不可读或格式不支持、动态壁纸软件（Lively、Wallpaper Engine 等）正在运行时，不设置壁纸，在设置页说明原因；图标玩法照常。

**多显示器**：第一版所有显示器使用同一张合成图（`SystemParametersInfoW`）；按显示器分别合成留待后续版本，不伪称已支持。

**禁止项**：不挂接 WorkerW、不建全屏或桌面层窗口、不运行外部壁纸程序、不修改原壁纸文件、不改主题与锁屏。Windows 主题同步是否会把合成壁纸带到其他设备，必须实测后记录。
